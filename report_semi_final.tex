\begin{abstract}
We address the lack of a usable French--Swahili--Lingala code-switched retrieval benchmark for eastern DRC speech technology. In eastern DRC cities such as Goma and Bukavu, many speakers use Swahili as the structural base of everyday speech while fluidly inserting French for official or technical terms and Lingala for emphasis, slang, or social nuance. Our approach is to build a synthetic trilingual corpus, derive a controlled text-to-text retrieval benchmark, and validate the benchmark with a simple lexical baseline before training stronger multilingual or cross-modal models. The resulting corpus contains 9{,}000 text items and 623 aligned synthetic audio clips. The benchmark contains 164 test queries, each evaluated against 50 candidates with one gold target, nine hard negatives, and forty random negatives. A TF-IDF word-bigram baseline reaches 0.5803 MRR, 0.4085 Recall@1, and 0.6232 nDCG@5. Our main contributions are the benchmark itself, a fully specified evaluation protocol, and an error analysis showing that failures cluster around orthographic near-duplicates, same-template lexical substitutions, and Lingala-bearing switch tokens. The main limitation is that all results are bounded to this synthetic corpus.
\end{abstract}

\section{Introduction}
Low-resource speech technology for the Democratic Republic of Congo lacks a usable benchmark for French--Swahili--Lingala code-switched retrieval. This is the specific problem addressed in this paper. We focus on retrieval because it is a practical first task for multilingual speech systems and because a benchmark is necessary before stronger encoders or audio-text models can be compared fairly.

The problem is important because these languages appear together in real communication contexts, including humanitarian and public-service settings \cite{kimanuka2025tods}. Prior work on Congolese Swahili speech translation already shows that the region is important and technically challenging \cite{denisov2021ims}. More broadly, recent work on code-switched speech and multilingual retrieval shows that benchmark availability strongly shapes what can be measured and improved \cite{yan2025csfleurs}\cite{hillah2024joint}\cite{cui2015multilingual}.

The problem is hard because naive approaches fail in two different ways. First, there is no public benchmark in the exact French--Swahili--Lingala setting, so model evaluation is not standardized. Second, code-switched retrieval is difficult even when data exists: surface lexical overlap can be misleading, orthographic variation is common, and code-switch points can alter meaning or disrupt matching. A purely lexical model can therefore perform well on some synthetic siblings but still fail on minimally different hard negatives.

The problem has not been solved before because previous resources do not match the target setting. Existing corpora cover Congolese Swahili speech translation \cite{denisov2021ims}, multilingual synthetic code-switched evaluation \cite{yan2025csfleurs}, or code-switching in other languages and tasks \cite{xie2025switchlingua}\cite{sailaja2025switchlangai}. Supporting resources such as Gamayun, WaxalNLP, Common Voice French, SERENGETI, and AfriBERTa are useful building blocks, but none of them directly provides a French--Swahili--Lingala code-switched retrieval benchmark with frozen evaluation splits \cite{gamayun-kit}\cite{gamayun-data}\cite{google-waxalnlp}\cite{common-voice-fr}\cite{serengeti}\cite{afriberta}. Our work differs by constructing and documenting that benchmark explicitly.

Our approach is to build a synthetic trilingual corpus, derive a controlled retrieval benchmark from the frozen test split, run a TF-IDF word-bigram baseline, and analyze the observed failures. The main result is that the benchmark is usable and non-trivial: the baseline reaches 0.5803 MRR, 0.4085 Recall@1, and 0.6232 nDCG@5 on 164 queries, while manual inspection shows systematic failure modes rather than random errors. The main limitations are that the benchmark is synthetic, the switch-band distribution is imbalanced, and source-family overlap across splits must be fixed before training stronger learned models.

\section{Data and Benchmark}
\subsection{Corpus Construction}
The corpus was created from parallel French--Swahili and French--Lingala sentence sources, then expanded with rule-based code-switching and copy-switch variation. The generator follows the Matrix Language Frame intuition: one language provides the grammatical frame, while embedded spans come from the other languages \cite{myers-scotton1993}. In our corpus, Swahili is usually the matrix language.

An example from the released text set is: \emph{Leo tuko na probleme ya maji, mairie ilisema travaux zinaanza kesho matin.} The sentence keeps a Swahili frame while inserting French content words. This is the type of mixed-language input that the benchmark is meant to test.

Table~\ref{tab:data} summarizes the released resources. The text set contains 9{,}000 items. The aligned audio subset contains 623 synthetic clips. The audio is useful for future cross-modal experiments, but this report evaluates only text-to-text retrieval because the text benchmark is the most stable part of the pipeline at this stage.

\subsection{Benchmark Construction}
The retrieval benchmark is derived from the text test split. We keep only test items that have a valid paired target from the same synthesis lineage, which yields 164 queries rather than all 900 test examples. Each query is evaluated against a fixed candidate pool of size 50: one gold target, nine hard negatives, and forty random negatives.

This controlled setup follows the logic of benchmark-driven evaluation used in recent low-resource retrieval work. It lets us test whether a model can recover the intended paired item under hard distractors instead of rewarding trivial exact-match retrieval.

The benchmark is imbalanced by switch band. Out of 164 queries, 154 are low-switch, 7 are medium-switch, and 3 are high-switch. This matters for interpretation: any high-switch conclusion is based on only three queries. The benchmark also contains 34 Lingala-bearing queries and 130 queries without Lingala.

One important limitation emerged during audit. The exported \texttt{text\_leakage\_report.csv} shows that 1{,}472 source families appear in more than one split, including 138 families that appear in train, dev, and test. The TF-IDF baseline reported here does not train on the train split, so this overlap does not inflate the current scores. However, future learned models should use a family-disjoint split.

\subsection{Metrics}
We report Mean Reciprocal Rank (MRR), Recall@1, and nDCG@5. MRR is the primary metric because it measures how early the correct item appears. Recall@1 captures whether the first result is correct. nDCG@5 summarizes the quality of the top of the ranked list. We also compute a simple code-switch robustness score:
\begin{equation}
\mathrm{CSRS}=\frac{\mathrm{MRR}_{\mathrm{high}}}{\mathrm{MRR}_{\mathrm{low}}}.
\end{equation}

The evaluation code also includes paired bootstrap resampling for ranking metrics and McNemar's test for Recall@1. In this report, however, only one actual model was run. The only statistical test we can report honestly is the self-comparison sanity check, which gives zero deltas and $p=1.0$ for every metric. We therefore present descriptive results only, not a meaningful model-versus-model significance claim.

\section{Baseline Model}
We use a TF-IDF word-bigram retriever. This is a weak but useful baseline. It checks whether the benchmark construction, candidate pools, ranking code, and exported metrics behave correctly before we invest in multilingual encoders or audio-text models.

This choice is also intentionally conservative. The synthetic corpus contains many near-paraphrases from the same generation lineage, so a lexical baseline should perform above random if the benchmark is well formed. At the same time, strong errors on hard negatives are still informative because they reveal where lexical overlap is insufficient.

This suggests that the baseline is less stable when Lingala tokens appear, which is plausible given the smaller amount of Lingala-bearing material and the lexical nature of the model.

\section{Error Analysis}
We manually inspected the 20 worst failed queries, using the exported per-query ranks and the paired gold texts. Because the current CSV export stores rank metrics but not the top-ranked distractor text, this analysis focuses on what makes the gold pair hard rather than on the full ranked list. Even with that limitation, the failure patterns are clear.

We observed three recurring categories. First, 7 of the 20 failures are orthographic near-duplicates, where the query and gold differ by light suffix noise such as \emph{wanataka} versus \emph{wanatakae} or \emph{routes} versus \emph{routese}. Second, 5 failures are same-template lexical substitutions, where the overall topic is preserved but one or two key words are replaced. Third, 8 failures involve Lingala-bearing or switch-token substitutions such as \emph{soki}, \emph{batu}, or \emph{bazali}. These tokens often preserve surface overlap while changing which paired item is correct.

These errors show that the benchmark is not trivial. The model is not simply failing on unrelated negatives. It often faces highly similar candidates from the same synthetic template family and cannot reliably separate the intended pair from minimal orthographic or lexical changes. This is exactly the type of behavior we wanted the first benchmark to expose.

\section{Discussion}
Two conclusions are supported by the current evidence. First, the project now has a usable benchmark: the dataset is frozen, the candidate pools are fixed, the evaluation metrics are exported, and the baseline produces interpretable successes and failures. Second, the reported scores are properties of this synthetic benchmark, not evidence about spontaneous DRC speech.

The benchmark is still early-stage and its limitations matter. The switch-band imbalance is severe, the audio subset is small, and the source-family overlap across splits must be fixed before training stronger learned models. The current results are therefore best understood as benchmark-validation results, not as evidence that the retrieval problem is solved for eastern DRC speech.

\section{Future Work}
The most important next step is to obtain a proper local voice dataset from eastern DRC. We already prepared the community-collection path because a realistic benchmark will eventually require real speakers from places such as Goma and Bukavu, not only synthetic renderings. That future dataset should better capture the fluid way local speakers move across Swahili, French, and Lingala within a single utterance.

The next experimental phase will follow the broader plan already defined for the project. On the text side, we plan to evaluate SERENGETI as the main multilingual African-language encoder and AfriBERTa as a low-resource African-language text baseline \cite{serengeti}\cite{afriberta}. On the cross-modal side, we plan to fine-tune a CLAP-style architecture to align audio and text representations and to compare that setup with a CLASP-style alternative for multilingual audio-text retrieval \cite{elizalde2019crossmodal}\cite{nuga2025multilingual}. These experiments will cover text-to-text, text-to-audio, and audio-to-text retrieval.

We will keep MRR as the primary ranking metric and continue to report Recall@1, nDCG@5, and the code-switch robustness score. Once multiple real models are run, we will use the existing paired bootstrap and McNemar testing code to support actual between-model significance claims rather than descriptive single-model reporting.

\section{Conclusion}
This report turns the project from an idea into an experimental asset. We produced a documented synthetic French--Swahili--Lingala corpus, derived a controlled retrieval benchmark from it, and showed that even a simple lexical baseline yields informative successes and failures. The benchmark now gives us a concrete starting point for stronger multilingual and cross-modal retrieval experiments.

The main value is not the TF-IDF score by itself. The main value is that we now have a reproducible benchmark, explicit limitations, and a clear next path toward real eastern DRC voice data and stronger retrieval models.
